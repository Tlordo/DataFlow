вопросы ответы по шагам

шаг 0


зачем в решении два проекта а не один
ответ: один проект это консольное приложение которое запускается, второй библиотека с обобщёнными классами. библиотеку вынесли отдельно чтобы её можно было использовать в других проектах и чтобы в ней не было типов предметной области

что произойдёт если убрать dotnet add reference
ответ: демо проект не увидит типы ядра и сборка упадёт с ошибкой что Buffer не найден

почему проект библиотеки нельзя запустить а консольный можно
ответ: у библиотеки нет точки входа (метода Main), она только хранит классы для других проектов

шаг 1


чем protected отличается от private и от public для этого поля
ответ: protected поле видно в самом классе и в наследниках, а снаружи нет. если сделать private то наследник LabeledBuffer не сможет обратиться к items. если сделать public то список откроется всем и его можно будет менять в обход TryAdd

что означает readonly и запрещает ли оно добавлять элементы
ответ: readonly запрещает присвоить полю новый список после создания. добавлять элементы можно, потому что меняется содержимое списка а не сама ссылка

зачем TryAdd возвращает bool если сейчас всегда true
ответ: чтобы наследники могли отклонять элементы. в базовом классе всегда true, а GuardedBuffer возвращает false если элемент не прошёл проверку

что будет если убрать virtual
ответ: метод нельзя будет переопределить и override в GuardedBuffer выдаст ошибку компиляции

чем new() отличается от new List()
ответ: по результату ничем, new() это сокращённая запись, тип компилятор берёт из объявления поля


шаг 2


чем LabeledBuffer : Buffer отличается от GuardedBuffer : Buffer
ответ: LabeledBuffer фиксирует T как string и становится обычным не обобщённым классом. GuardedBuffer оставляет T открытым и работает с любым типом. первое нужно когда поведение подходит только для конкретного типа, второе когда расширяем поведение для всех типов

почему PrintAllUpper нельзя написать в Buffer
ответ: в Buffer компилятор не знает что такое T и что у него есть ToUpper. в LabeledBuffer T точно string

что будет если объявить LabeledBuffer
ответ: ошибка компиляции, LabeledBuffer не обобщённый и не принимает параметр типа

смог бы LabeledBuffer хранить числа если бы наследовался от Buffer
ответ: да, но тогда туда можно положить что угодно, ToUpper не скомпилируется без приведения к string, а ошибки будут вылезать только во время работы программы. типовая безопасность пропадает


шаг 3


почему проверка отказа стоит до вызова базового метода
ответ: чтобы отклонённый элемент вообще не попал в список. если проверять после, элемент уже будет добавлен

что будет если считать AcceptedCount до проверки результата базы
ответ: счётчик будет расти и на отклонённых элементах и перестанет совпадать с Count

чем отличается GuardedBuffer и GuardedBuffer если код один
ответ: отличается только T и правило которое передали в конструктор: для int x > 0, для string проверка на пустую строку. у каждого экземпляра свой счётчик

почему нельзя вместо base.TryAdd написать items.Add
ответ: тогда логика добавления дублируется, и если базовый класс поменяет правила, наследник про это не узнает. задание проверяет именно переиспользование базового метода

что будет если перенести условие внутрь класса
ответ: класс перестанет быть универсальным, условие подойдёт только для одного типа, например x > 0 не скомпилируется для string


шаг 4


чем struct отличается от class для вызывающего кода
ответ: struct передаётся по значению, при присваивании создаётся копия и изменение копии не меняет оригинал. class передаётся по ссылке, две переменные указывают на один объект

что выведет Console.WriteLine(record) без ToString
ответ: имя типа DataFlow.Core.Record`1[System.Double] вместо значения

как компилятор понял что TResult = string во втором вызове
ответ: по тому что возвращает лямбда: c >= 15 ? "тепло" : "холодно" возвращает string. T он понял по Record

почему нельзя было сделать отдельные методы ToFahrenheit и ToCategory
ответ: можно, но тогда на каждое преобразование нужен свой метод и код дублируется. Map один и работает с любыми парами типов, меняется только лямбда

что будет если убрать ToString, увидит ли проверяющий
ответ: да, в выводе вместо "°C: 20" будет имя типа и это сразу видно


шаг 5


что будет если убрать where T : IEntity
ответ: компилятор не даст обратиться к item.Id, потому что не знает что у T есть Id

почему ограничение проверяется компилятором а не во время выполнения
ответ: типы подставляются при компиляции и компилятор сразу знает подходит тип или нет, ошибку видно до запуска

что означает T? в GetById и чем это отличается от Nullable
ответ: T? значит что метод может вернуть null если элемента нет. здесь это просто пометка для проверки на null. Nullable это отдельная обёртка для значимых типов, а тут если T окажется структурой, T? останется обычным T и вернётся значение по умолчанию а не null

что будет если добавить в IContainer метод void Put(T item)
ответ: ошибка CS1961, out T разрешает T только на выходе, а Put принимает T на входе


шаг 6


почему where T : IEntity нужно указывать и на интерфейсе и на реализации
ответ: класс объявляет свой собственный параметр T, ограничение с интерфейса на него само не переходит, и без where компилятор не знает что у T есть Id

что означает return default для ссылочного типа и для int
ответ: значение по умолчанию: для ссылочного типа null, для int 0

что будет если вернуть null, какой код ошибки
ответ: ошибка CS0403, null вернуть нельзя потому что T может оказаться структурой

почему items здесь private а в Buffer protected
ответ: в Buffer поле нужно наследникам, а репозиторий никто не наследует, список это деталь реализации и доступ к нему только через методы интерфейса


шаг 7


почему IContainer принимает Container а Container нет
ответ: интерфейс объявлен с out T, он ковариантный и T только на выходе, поэтому Dog можно отдать как Animal. класс инвариантный, Container и Container для компилятора разные типы

какую цену заплатили объявив out T
ответ: в интерфейс нельзя добавить метод который принимает T как параметр

зачем класс помечен sealed
ответ: чтобы от Container никто не наследовался и не добавлял методы которые принимают T, класс закрыт для расширения

пример где IContainer полезнее чем Container
ответ: метод void Show(IContainer c) который печатает животное. в него можно передать Container, Container и т.д., а с Container пришлось бы писать отдельный метод под каждый тип


шаг 8


что будет если заменить IEnumerable на List
ответ: метод будет работать только со списками, массивы, результат Where и другие коллекции перестанут подходить

зачем в FindMax where T : IComparable
ответ: без него не скомпилируется item.CompareTo(best!), компилятор не знает что у T есть CompareTo

почему нельзя заменить на Max() из LINQ
ответ: Max на пустой последовательности бросает исключение, а по заданию метод не должен бросать

чем return default отличается от return null
ответ: return null не скомпилируется если T может быть структурой, а default работает всегда. в выводе видно: на пустом List null, на пустом List 0

что означает best! и почему без него не собирается
ответ: это оператор подавления null, говорим компилятору что best точно не null (это гарантирует found). без него будет предупреждение, а сборка по заданию должна быть без предупреждений


шаг 9


что будет если удалить Id из Product
ответ: Product перестанет реализовывать IEntity, будет ошибка компиляции, и его нельзя будет положить в InMemoryRepository

зачем CompareTo принимает Product? а не Product
ответ: по контракту IComparable в сравнение может прийти null, поэтому метод должен это обработать

что будет если CompareTo всегда возвращает 1
ответ: каждый элемент будет считаться больше предыдущего и FindMax просто вернёт последний элемент

как изменится вывод PrintAll без ToString
ответ: вместо "Яблоко (120,00)" будет печататься имя типа Product с пространством имён

почему Customer не реализует IComparable а Product реализует
ответ: клиентов не нужно сравнивать и FindMax для них не используется, IComparable подключается только там где нужно


шаг 10


почему OutputEncoding выставлен первой строкой
ответ: кодировка должна стоять до первого вывода, иначе строки с кириллицей выведутся кракозябрами

что доказывает что GuardedBuffer универсален
ответ: один и тот же класс работает и с int и со string, у обоих правильно отклоняются элементы и считаются счётчики

по какой строке видно что счётчики независимы
ответ: "Счётчики независимы: numbers.AcceptedCount = 2" после того как у words было 1, и "products.Count = 2, customers.Count = 1"

где тип Record изменился с double на string
ответ: "double → string: Категория: тепло". метод Map один, а TResult стал string из за лямбды

что покажут строки про пустой List и почему это не ошибка
ответ: покажут 0, это default(int). FindMax не бросает исключение а возвращает значение по умолчанию


шаг 11


почему ошибка 1 есть для класса но нет для интерфейса
ответ: интерфейс объявлен с out T и он ковариантный, а классы всегда инвариантные, вариантность у них не поддерживается

что изменится в ошибке 2 если заменить out T на in T
ответ: Put станет нормальным, но ошибка появится на GetItem, потому что in T разрешает T только на входе, а GetItem возвращает T

какие ещё типы нельзя подставить в InMemoryRepository
ответ: все которые не реализуют IEntity: int, object, Animal, Dog и т.д.

почему компилятор ловит все три ошибки до запуска
ответ: все три правила про типы, а типы компилятор проверяет при сборке

что значит проверка на этапе компиляции для цены ошибки
ответ: ошибку находят сразу при сборке а не у пользователя во время работы программы, исправить её намного дешевле
